# 13. 시스템 통합 (웹 서비스·피드백·통합 테스트) — 소스 설명

대응 노트북: `notebooks/13_시스템통합_웹서비스_센서영상_통합테스트.ipynb`

## 한눈에 보기

11·12번 모듈을 **하나의 웹 서비스 흐름**으로 묶고,  
운영자 **피드백**으로 임계값/가중치를 갱신하며,  
End-to-End **통합 테스트**로 인수 기준을 검증합니다.

산출물: `outputs/system_integration/`

## 초보자를 위한 용어 사전

| 용어 | 쉬운 설명 |
|------|-----------|
| **End-to-End (E2E)** | 입력이 들어가 최종 출력까지 전체 경로를 한 번에 검증. |
| **피드백 루프** | 사람 판정 결과를 다시 시스템에 넣어 설정을 개선하는 순환. |
| **임계값 (threshold)** | HIGH/MEDIUM을 나누는 점수 기준선. |
| **인프로세스** | 별도 서버 없이 같은 파이썬 프로세스 안에서 API처럼 호출. |
| **SLA** | 서비스 수준 합의. 예: 가용성 99.5%, 응답시간 목표. |
| **인수 기준** | ‘이 정도면 통과’라고 정한 테스트 조건. |

## 핵심 클래스

### `ServiceConfig`

운영 중 바뀌는 설정: `w_vision`, `w_sensor`, `risk_high`, `risk_medium` 등.  
JSON으로 저장/로드.

### Vision / Sensor / Fusion / MockLLM

13번용 경량 버전. Sensor는 **최근 윈도우의 |z| 최대**로 중간 이상도 잡도록 개선.

### 웹 서비스 레이어

이미지+센서 → analyze → fusion + LLM 응답 JSON.

### 피드백

운영자가 “맞음/틀림”을 남기면 가중치·임계값 조정 로직으로 연결.

## 통합 테스트가 보는 것

- 정상 입력 → 200성 응답(성공)
- 깨진 센서 → 품질 실패 또는 안전 처리
- HIGH 리스크 시 조치 필드 존재
- 피드백 반영 후 config 변경 여부

## 아키텍처

```text
이미지+센서 → Vision/Sensor → Fusion → LLM → API 응답
                ↑
         Feedback Store → Config 갱신
```
