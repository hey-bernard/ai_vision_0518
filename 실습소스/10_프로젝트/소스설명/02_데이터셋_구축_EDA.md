# 02. 데이터셋 구축 및 EDA — 소스 설명

대응 노트북: `notebooks/02_데이터셋_구축_EDA.ipynb`

## 한눈에 보기

데이터를 **열어보고, 세고, 그려보고, 이상한 점을 찾는** 단계입니다.

EDA = Exploratory Data Analysis = **탐색적 데이터 분석**  
(아직 모델을 깊게 학습하기 전에 “데이터가 어떤 모양인지” 파악)

## 초보자를 위한 용어 사전

| 용어 | 쉬운 설명 |
|------|-----------|
| **EDA** | 데이터를 표·그래프로 살펴 패턴과 문제를 찾는 과정. |
| **split (분할)** | 학습(train) / 검증(val) / 시험(test)으로 데이터를 나눈 구역. |
| **stem** | 파일 이름에서 확장자를 뺀 부분. 예: `a.jpg`의 stem은 `a`. |
| **정합성** | 이미지와 라벨이 짝이 맞는지(같은 이름인지) 확인하는 것. |
| **정규화 좌표** | 박스 좌표를 0~1 사이 비율로 적은 것. 이미지 크기가 달라도 공통으로 씀. |
| **cx, cy, w, h** | 박스 중심 x, 중심 y, 너비, 높이 (YOLO 형식). |
| **클래스 불균형** | 어떤 결함은 많고 어떤 결함은 적은 상태. 모델이 많은 쪽만 잘 맞힐 수 있음. |
| **메타데이터** | 데이터에 대한 부가 정보(조명, 해상도, 회전 등). |
| **증강 (augmentation)** | 회전·뒤집기 등으로 데이터를 늘려 학습에 쓰는 기법. |
| **어노테이션** | 사람이(또는 도구가) 붙인 정답 표시. 여기선 bbox 라벨. |

## 폴더 구조 (코드가 가정하는 형태)

```text
pcb-defect-dataset/
├── train/images , train/labels
├── val/images   , val/labels
└── test/images  , test/labels
```

라벨 한 줄 예:

```text
2 0.51 0.44 0.08 0.06
```

→ 클래스 2번 결함이, 중심 (0.51, 0.44), 크기 (0.08 × 0.06)

## 주요 함수 설명

### `count_split(split)`

이미지 개수, 라벨 개수, **서로 짝이 맞는 stem 수**, 이미지만/라벨만 있는 수를 셉니다.

### `parse_filename(stem)`

파일명에서 `light`, `rotation`, 해상도(256/600) 등을 정규식으로 뽑습니다.

### `load_yolo_labels` / `build_annotation_dataframe`

모든 라벨을 읽어 **한 행 = 박스 하나**인 큰 표(DataFrame)를 만듭니다.

### `draw_yolo_boxes`

정규화 좌표를 픽셀 좌표로 바꿔 이미지 위에 네모와 클래스 이름을 그립니다.

```text
픽셀 x = (cx - w/2) × 이미지너비
픽셀 y = (cy - h/2) × 이미지높이
```

## 품질 검증이 보는 것

- 좌표가 0~1 밖인가?
- class_id가 0~5가 아닌가?
- 박스가 너무 작거나 큰가?
- 파일명의 결함명과 라벨 클래스가 대체로 맞는가?

## 실행 흐름

```text
경로/설정 로드 → split 개수 확인 → 파일명 파싱
→ 전체 bbox 표 생성 → 클래스/조명/해상도 그래프
→ 샘플에 박스 그리기 → 품질 리포트
```
