# 07. 시각 데이터 구성 및 모델 성능 평가 — 소스 설명

대응 노트북: `notebooks/07_시각데이터구성_모델성능평가.ipynb`

## 한눈에 보기

YOLO **객체 검출** 라벨을, 연습용으로 **이미지당 대표 클래스 하나**로 바꿔  
가벼운 **분류 baseline**을 학습·평가합니다.

목적: 복잡한 딥러닝 전에 **데이터 파이프라인이 돌아가는지** 확인.

산출물: `outputs/model_eval/`

## 초보자를 위한 용어 사전

| 용어 | 쉬운 설명 |
|------|-----------|
| **baseline** | 비교 기준이 되는 아주 단순한 모델. ‘이보다 나아야 의미 있다’. |
| **Nearest Centroid** | 클래스별 Feature 평균(중심)을 구해, 가장 가까운 중심으로 분류. |
| **Confusion Matrix** | 진짜 클래스 vs 예측 클래스를 표로 세어 어디서 헷갈리는지 봄. |
| **Accuracy** | 전체 중 맞춘 비율. |
| **Macro F1** | 클래스마다 F1을 구한 뒤 평균. 소수 클래스도 동등하게 봄. |
| **F1** | Precision과 Recall의 조화평균. 둘 다 어느 때만 높아짐. |
| **support** | 해당 클래스 샘플 개수. |

## 대표 클래스 규칙

한 이미지에 박스가 여러 개면:

1. 가장 많이 나온 class
2. 동률이면 **작은 class_id**

> 실무에서는 보통 검출 그대로 학습하거나 멀티라벨을 씁니다. 여기는 실습 단순화입니다.

## 코드 흐름

```text
이미지 표 구성 → 통계 Feature 추출
→ train centroid 학습 → val/test 예측
→ Precision/Recall/F1 + Confusion Matrix 저장
```

## 해석 팁

성능이 낮아도 정상일 수 있습니다. 원인 후보:

- 클래스 불균형
- 비슷한 결함이 Feature에서 겹침
- 검출 → 단일 클래스 변환으로 정보 손실
