# 06. 산업 데이터 전처리 및 정제 — 소스 설명

대응 노트북: `notebooks/06_산업데이터_전처리_정제_실습.ipynb`

## 한눈에 보기

현장 데이터에는 **짝 안 맞는 파일, 빈 라벨, 좌표 오류, 센서 결측/스파이크**가 흔합니다.  
이 노트북은 그걸 찾아 **리포트로 남기고, 정제본을 저장**합니다.

산출물 폴더: `outputs/data_cleaning/`

## 초보자를 위한 용어 사전

| 용어 | 쉬운 설명 |
|------|-----------|
| **전처리 / 정제** | 모델에 넣기 전에 오류를 고치고 형식을 맞추는 작업. |
| **결측치** | 값이 비어 있음 (NaN). 센서 통신 끊김 등에서 발생. |
| **이상치 (outlier)** | 정상 범위를 크게 벗어난 값. 진짜 이상일 수도, 센서 오류일 수도 있음. |
| **IQR** | 사분위수 범위(Q3-Q1). 이 밖으로 멀리 나간 값을 이상치로 보는 방법. |
| **보간 (interpolate)** | 빈칸을 앞뒤 값으로 부드럽게 채우는 것. |
| **clip / winsorize** | 너무 큰/작은 값을 상한·하한으로 잘라 넣는 것. |
| **인벤토리** | split별 이미지/라벨 개수 등 ‘재고 조사’ 표. |

## 파이프라인 단계

1. **인벤토리**: train/val/test 이미지·라벨 매칭 수
2. **라벨 품질**: 형식, class, 좌표, tiny/huge bbox, 이미지 없는 라벨
3. **메타데이터 정규화**: 파일명 → light/rotation/resolution 컬럼
4. **센서 정제**: 결측 보간 → IQR clip → rolling/diff feature
5. **리포트 저장**: CSV + `cleaning_report.json`

## 핵심 함수

- `parse_label_file`: 한 라벨 파일에서 bbox와 이슈 목록 반환
- `build_label_quality_table`: 전체 split 스캔
- `parse_stem`: 파일명 정규식 파싱
- `iqr_clip`: 이상치 클리핑

## 왜 중요한가?

나쁜 라벨/센서가 그대로 들어가면, 모델이 **틀린 정답**을 배웁니다.  
정제는 “청소”가 아니라 **학습 가능 상태로 만드는 공정**입니다.
