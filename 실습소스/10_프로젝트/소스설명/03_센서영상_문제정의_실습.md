# 03. 센서·영상 데이터 문제 정의 실습 — 소스 설명

대응 노트북: `notebooks/03_센서영상_문제정의_실습.ipynb`

## 한눈에 보기

카메라는 **사진**, 센서는 **숫자 시계열**(밝기·온도·진동 등)입니다.  
둘을 같이 쓰는 것을 **멀티모달(multimodal)** 이라고 합니다.

이 노트북은 실제 센서 파일이 없어도, 파일명의 조명 ID로 센서 값을 **시뮬레이션**해 시나리오를 설계합니다.

## 초보자를 위한 용어 사전

| 용어 | 쉬운 설명 |
|------|-----------|
| **멀티모달** | 서로 다른 종류의 데이터(영상+센서+텍스트 등)를 함께 쓰는 방식. |
| **시뮬레이션** | 실제 장비가 없어도 규칙/난수로 ‘비슷한 값’을 만들어 보는 것. |
| **조도 (lux)** | 빛이 얼마나 밝은지. 조명 센서 단위. |
| **시계열** | 시간이 흐르며 순서대로 쌓인 값들. |
| **상관계수** | 두 값이 같이 움직이는 정도. 1에 가까우면 비슷하게 움직임. |
| **이상 탐지** | ‘정상’만 알고 ‘이상한 것’을 찾아내는 과제 (라벨이 적을 때 유용). |
| **예지 보전** | 고장 나기 전에 센서 패턴으로 미리 정비하는 것. |
| **confidence** | 모델이 ‘얼마나 확신하는지’ 점수 (보통 0~1). |
| **cascade** | 1차로 빠르게 보고, 애매하면 2차로 더 자세히 보는 단계적 구조. |
| **어노테이션 품질** | 정답 라벨이 얼마나 정확한지. 모델 성능의 천장(상한)을 결정. |

## 코드 핵심

### 센서 시뮬레이션

```python
lux = 800 + light_id * 120 + 노이즈
temp = 시간에 따라 서서히 상승 + 노이즈
speed, vibration = 난수 분포
```

이미지 평균 밝기와 lux를 산점도로 그려 **센서 ↔ 영상** 관계를 확인합니다.

### 의사결정 트리 `run_decision_tree`

질문 예:

1. 결함 **위치**가 필요한가? → Yes면 객체 검출
2. 라벨이 충분한가? → No면 이상 탐지
3. 센서가 영상과 동기화돼 있는가? → Yes면 융합 검토

본 프로젝트 답: **위치 필요 → 객체 검출**, 센서는 아직 보조.

### 라벨 품질 스캔

빈 라벨, 잘못된 class, 너무 작은/큰 bbox, 중심 좌표 이탈을 `issues`로 모읍니다.

### Cascade 시뮬레이션

Vision confidence가 0.7 미만인 샘플에 센서 이상 점수를 더해 2차 판정 아이디어를 보여 줍니다.

## 실행 흐름

```text
영상 메타 파싱 → 센서 값 생성 → 상관/분포 그래프
→ ML 과제 매트릭스 → 의사결정 트리
→ 라벨 품질 점검 → cascade 개념 실습
```
